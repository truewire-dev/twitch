# Twitch, typed

A typed, validated, async Python client for the [Twitch](https://www.twitch.tv) Helix API — accounts, live broadcasts, videos, clips, categories and channels, every list of them paged by cursor — and for EventSub over WebSocket, the socket Twitch pushes live events down. Generated by [Truewire](https://truewire.dev) from a spec of what the API puts on the wire, so every response is checked against the shape the API recorded, not the shape someone remembered.

Helix authenticates everything, public data included. Register an application at [dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps) for a client id and a client secret; the client exchanges the pair for an app access token the first time a call needs one, caches it until just before it expires, and mints a new one when Twitch says the old one is gone. That pair is all every endpoint here needs but one, which wants a token a person has to grant.

## Install

Not on PyPI yet; install from the repository:

```sh
pip install git+https://github.com/truewire-dev/twitch
```

The import name is `twitch_helix`, and the distribution is `truewire-twitch`. Python 3.11 or newer.

## Use

`TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` in the environment are all `Twitch.new()` needs; pass them as `client_id=` and `client_secret=` instead if they live somewhere else. Neither value is read until a call needs a token, and neither is ever rendered: a `Secret` prints as `******` in every repr, and both travel in headers, which no recording holds.

```python
import asyncio

from twitch_helix import Twitch


async def main() -> None:
  async with Twitch.new() as client:
    account = await client.users.get(login=['twitchdev'])
    user = account['data'][0]
    print(user['display_name'], '·', user['id'], '·', user['broadcaster_type'])
    print('joined', user['created_at'].date())

    live = await client.streams.get(game_id=['509670'], first=3)
    for stream in live['data']:
      print(f'{stream["viewer_count"]:>6} {stream["user_login"]:<16} {stream["title"][:40]}')


asyncio.run(main())
```

Every method is typed from the request Twitch documents (`type` is a `Literal` of the two values `/helix/streams` accepts, `first` an `int` with the documented range in its docstring), and returns a `TypedDict` validated against the recorded wire shape. Timestamps come back as `datetime`: `created_at`, `started_at`, `published_at` and every EventSub `message_timestamp` parse from RFC 3339. `validate=False` on a call returns the parsed body as it came, typed `Any` — which is how you reach a field the schema does not name.

### The envelope stays

Helix wraps every answer in `{"data": [...], "pagination": {...}}`, and this client hands that frame back rather than unwrapping `data`. It is a real decision, not an oversight, and it is the same decision on all nine Helix methods, so there is nothing to remember per endpoint: **the rows are always `result['data']`**.

Two reasons. The cursor for the next page lives *beside* `data`, not inside it, so unwrapping would put it out of reach of the generated walk — the walk reads its state off exactly what the method returns. And the EventSub frames carry `total`, `total_cost` and `max_total_cost` next to `data`; those are answers a caller wants, not packaging to index past.

### Paging

Five of the endpoints hand back a cursor. Each one has a `_paged` twin that walks it: awaited it flattens every page, iterated it yields one page's rows at a time, and `pages()` gives each page with the cursor on either side of it, so a walk can be checkpointed and resumed.

```python
from twitch_helix import Twitch


async def every_category() -> None:
  async with Twitch.new() as client:
    walk = client.games.top_paged(first=100)
    async for page in walk.pages():
      for game in page.rows:
        print(game['id'], game['name'])
      if page.next is None:
        break
```

Twitch ends a walk by sending `pagination` as an **empty object** — not by dropping the key, and not with a null cursor — so a page whose `pagination` holds no `cursor` is the last one, and that is what the walk stops on.

### EventSub

EventSub is two halves that only work together, and the seam is a session id.

Opening `client.websocket.events()` connects to the socket, and the first message is always a `session_welcome` carrying that id. Nothing is ever sent back up the socket — Twitch closes a connection that receives anything but a pong. Instead, the subscriptions are created over HTTP, with `client.eventsub.subscribe(...)`, naming the session id as the transport. From then on the events arrive as `notification` messages on that socket.

```python
from twitch_helix import Twitch


async def when_they_go_live(broadcaster_id: str, user_token: str) -> None:
  async with Twitch.new(user_access_token=user_token) as client:
    async with client.websocket.events(keepalive_timeout_seconds=30) as messages:
      async for message in messages:
        kind = message['metadata']['message_type']
        payload = message.get('payload')
        if payload is None:
          continue
        session = payload.get('session')
        if kind == 'session_welcome' and session is not None:
          # The socket is open; now say what should arrive on it.
          await client.eventsub.subscribe(
            type='stream.online',
            version='1',
            condition={'broadcaster_user_id': broadcaster_id},
            transport={'method': 'websocket', 'session_id': session['id']},
          )
        elif kind == 'notification':
          print(message['metadata'].get('subscription_type'), payload.get('event'))
        elif kind == 'session_reconnect' and session is not None:
          # Twitch is moving the connection; reopen on this URL before dropping the old one.
          print('reconnect to', session.get('reconnect_url'))
        elif kind == 'revocation':
          print('revoked:', payload.get('subscription'))
```

`session_keepalive` arrives whenever nothing else has for `keepalive_timeout_seconds`, and a gap longer than that means the connection is gone. `revocation` says a subscription has stopped and its `status` says why. The `event` object is a plain map: its fields are a fact about the subscription type, of which Twitch documents dozens, and `metadata['subscription_type']` is what says how to read it.

Creating a subscription is the one call here that needs a **user access token**, from an authorization code grant a person completes in a browser — the client credentials flow cannot mint one, and Twitch refuses a WebSocket subscription made with an app token. The client knows that before it makes the request: `Twitch.new()` without `user_access_token=` raises on `eventsub.subscribe(...)` rather than spending a round trip to be told no.

### The client's shape

| Method | Endpoint | What it answers |
| --- | --- | --- |
| `client.users.get(...)` | `GET /helix/users` | Accounts by id or login, up to 100 |
| `client.channels.get(...)` | `GET /helix/channels` | Channel settings: title, category, tags, labels |
| `client.streams.get(...)` | `GET /helix/streams` | Who is live right now, most watched first, paged |
| `client.videos.get(...)` | `GET /helix/videos` | Past broadcasts, highlights and uploads, paged |
| `client.clips.get(...)` | `GET /helix/clips` | Clips by clip, broadcaster or category, paged |
| `client.games.get(...)` | `GET /helix/games` | Categories by id, exact name or IGDB id |
| `client.games.top(...)` | `GET /helix/games/top` | The most watched categories, paged |
| `client.eventsub.subscribe(...)` | `POST /helix/eventsub/subscriptions` | Create a subscription against a session id |
| `client.eventsub.subscriptions(...)` | `GET /helix/eventsub/subscriptions` | The application's own subscriptions, paged |
| `client.websocket.events(...)` | `wss://eventsub.wss.twitch.tv/ws` | Every message the EventSub socket pushes |

The nine Helix methods share one host and one connection pool; the socket opens once per subscription and closes with the client.

### What is not here

Everything that changes something, and everything behind a user access token: modifying a channel, sending a whisper, moderation, the chat endpoints, subscriber and follower lists, analytics. Those need a user token and, mostly, a specific scope, and this client wraps none of the OAuth dance that gets one. `Twitch.new(user_access_token=...)` takes a token you already hold, which is what makes `eventsub.subscribe(...)` work; it does not add any endpoint.

`GET /helix/channels/followers` is a near miss worth naming: it looks like the paged endpoint it once was, but today it needs the broadcaster's own token with `moderator:read:followers`, so an app access token gets a follower count and nothing else. Deleting an EventSub subscription is a `204` with no body, which is a shape this client does not wrap yet.

## Recordings

Every endpoint carries the request half of at least one example — the exact parameters the tests and the recording script replay, against public channels like `twitchdev`. The response halves are recorded from the live API through this same generated client, so a recording is the wire body the client saw and the response types are proven against it, never written by hand. The machine this client was written on held no Twitch credentials, so it has none yet, and every endpoint says so on itself with the reason.

- [`test/recapture.sh`](test/recapture.sh) re-records everything. Run it locally with an application's client id and secret exported, or through the [Record workflow](.github/workflows/record.yml) (Actions, "Record", run workflow), which reads them from the repository secrets `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET`, records on a runner, and opens a pull request on a `record/<run id>` branch with the responses. It fails immediately, naming what is missing, if either secret is absent. The repository setting "Allow GitHub Actions to create and approve pull requests" (Settings, Actions, General) has to be on for the pull request.
- The nine Helix calls are recorded with `truewire capture`. The EventSub socket is not a request and a reply, so it is recorded by reading it for a bounded window through the same client ([`test/record_events.py`](test/record_events.py)). With only the application's credentials, what that records is the connect half — the welcome and the keepalives after it — because filling the socket needs a subscription, and a subscription needs a user token.
- Tests replay the recordings through the client against `truewire mock`, which serves them over real HTTP and a real WebSocket; nothing in the tests touches the network. Until a recording exists, its test skips and says why. The cursor walk does not wait for one: [`test/test_pagination.py`](test/test_pagination.py) drives it over three pages against an in-memory transport, because one page cannot tell a correct walk from one that stopped immediately.

```python
from twitch_helix import Twitch


async def against_the_mock(http: str, ws: str) -> None:
  # The mock answers a request that matches a recording exactly; these are the recorded
  # parameters. The credentials are fake on purpose: a client handed an app token never
  # asks Twitch for one, so nothing here leaves the machine.
  async with Twitch.new(
    base_url=http, ws_url=ws, client_id='TEST_CLIENT_ID', app_token='TEST_APP_TOKEN'
  ) as client:
    print((await client.users.get(login=['twitchdev']))['data'][0]['id'])
    async with client.websocket.events() as messages:
      async for message in messages:
        print(message['metadata']['message_type'])
```

The gates that run on every pull request: `truewire check` (the spec against its own rules and every recording against its schema), `truewire standards`, the generated code being current, pytest, pyright over [`test/typing_usage.py`](test/typing_usage.py), ruff. Every code block in this file is type-checked against the package.
